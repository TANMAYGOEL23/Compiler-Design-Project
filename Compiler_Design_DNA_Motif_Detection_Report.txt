1. COMPILER DESIGN CONNECTION (THEORY & CONCEPTS)
================================================================================
The fundamental objective of a Compiler's Lexical Analyzer (Lexer) is pattern
recognition over a stream of input tokens. In classical compiler theory, regular
expressions are compiled into Deterministic Finite Automata (DFAs) that consume
characters and transition between states to classify tokens using Boolean
accept/reject logic.

This project translates that compiler foundation into computational biology by
modeling variable DNA patterns as Weighted Finite Automata (WFAs):

• Finite Alphabet (Σ):
  DNA nucleotide alphabet Σ = {A, C, G, T}, extended with IUPAC degenerate
  symbols (R, Y, S, W, K, M, N) mapped to compiler input tokens.

• Lexeme / Token Pattern:
  The target transcription factor binding sites (e.g. GATA1, p53, CTCF, SP1)
  are treated as target lexical tokens.

• Automaton State Chain:
  States q0 → q1 → ... → qL represent milestone positions consumed in the sliding
  window.

• Weighted Transitions (W):
  Instead of binary transitions (e.g. G → next_state), each transition carries a
  log-odds weight derived from Position-Specific Scoring Matrices (PSSM):
  G / weight → next_state.
  The accumulated weight represents quantitative sequence affinity.

• 2D State Space q(i, k):
  Tracks motif position 'i' and consumed mismatch budget 'k' in state space q(i, k),
  enforcing error tolerance constraints (0 ≤ k ≤ K_max).

• Lookahead Branch-and-Bound Pruning:
  Prunes search branches when the remaining maximum suffix score cannot reach
  the required threshold, directly mirroring compiler dead-code elimination.


================================================================================
2. WHAT THE PROJECT ACHIEVES
================================================================================
• Solves Exact Match Rigidity:
  Traditional exact string matching / classical DFAs fail because biological
  transcription factors tolerate mutations. The WFA scores affinity probabilistically.

• 20-Motif Bank Registry:
  Expanded from a single motif to 20 biologically verified transcription factors
  (JASPAR profiles) spanning 6 bp to 20 bp (GATA1, CTCF, SP1, TATA, NF-kB, AP-1,
  p53, MYC, STAT3, FOXA1, ESR1, SOX2, OCT4, HNF4A, CREB1, E2F1, CEBPA, RUNX1,
  PAX6, MEF2A).

• 20-Genome Reference Registry:
  Provides 20 preloaded genomic loci across human chromosomes and model organisms
  (Human Chr11 HBB, Chr17 TP53, Chr8 MYC, Mouse Hbb, Zebrafish gata1a, Yeast,
  Viruses, Bacteria).

• Custom DNA Sequence Addition & Sequence Appending:
  Users can add brand new custom DNA sequences or append additional sequence bases
  directly to any selected genome ("add a dna seq after find a selected one").

• Modern Interactive Python UI (Tkinter/TTK):
  Native desktop GUI application (gui_app.py) featuring interactive motif selection,
  genome viewers, canvas automaton graph drawing, step-by-step tracers, and result tables.

4. SUMMARY & KEY TAKEAWAYS FOR REVIEW / VIVA
================================================================================
1. Why Automata?
   A standard compiler asks "Is this token valid?" (Boolean accept/reject).
   Our Weighted Finite Automaton asks "How strongly does this input match the
   pattern?" (Probabilistic log-odds scoring).

2. Why WFA over DFA?
   Exact regex matches only a few sites. The probabilistic WFA identifies
   hundreds of candidate regulatory sites, capturing biological mutation tolerance.

3. Why 2D Mismatch Automaton?
   The 2D state space q(i, k) explicitly tracks position and mutation budget,
   bridging compiler state-space tracking with biological error tolerance.

4. Rich Biological Breadth:
   Preloaded 20 transcription factors and 20 reference genomes, with an
   interactive desktop GUI and sequence appender.
